Transmission

A macOS desktop app for content audits. It pairs a spreadsheet with an embedded browser so you can review every page on a website and record structured decisions without switching apps.

KKE is the core call on every existing page: Keep · Kill · Evolve · Consolidate · Exclude. The input is usually a Screaming Frog crawl export (.xlsx), but any spreadsheet with a URL column works. Every decision is written back into the same file — your deliverable is one enriched spreadsheet. Changes auto-save moments after your last edit (≈0.4s in a project, 2s in a spreadsheet; or Cmd+S).

This help follows the real lifecycle of an audit, top to bottom (Set up → Audit → Classify → Review → Architect → Ship → Power features). Each section opens with the one mental model that makes it obvious, the key steps, and a Good end-state checklist. For the full manual and task hand-outs, see the project's docs/ folder (docs/USER_GUIDE.md and docs/walkthroughs/).

A · Set up & orient

1. Getting Started

Mental model — one portable file is the whole project. Start from a crawl spreadsheet, then convert it to a .transmission project file (File → Save As Project…, Cmd+Shift+S) — same single-file promise, but saves are instant at any size. Excel becomes the import/export format: File → Export Full Workbook (.xlsx)… produces a complete spreadsheet (all sheets + change history) whenever you need a deliverable.

  • Open: Cmd+O (or the welcome dialog's Open a file). Formats: .transmission, .xlsx, .xls, .xlsm, .ods, .csv. File → Open Recent lists the 10 latest. Project files also open by double-click in Finder.
  • Hand-off: File → Package for Handoff… saves, snapshots, and zips the project (with a README) ready to send; the recipient unzips and double-clicks. Change-log entries record each auditor's username. A rolling safety copy is kept in the app's support folder on every open.
  • Client exports: File → Export… → Client Export exports a chosen column subset (built-in Client Summary / Full, or your own saved profiles — stored in the project) over filtered or all rows.
  • Sheet & URL: multi-sheet files show a picker (structural sheets hidden); the URL column auto-detects (Address, URL, …) or you pick it.
  • Seed banners: one-time offers of starter libraries (Content Type Registry, Target Spec Library, Component Library). Seeding stages data — save to commit.
  • Help: Help → Getting Started (welcome), Product Tour (5-step), Keyboard Shortcuts (Cmd+/ or ?).

Good end-state

  • Right data sheet selected; URL column detected (rows load a page)
  • Audit columns + structural sheets present; seed banners handled deliberately
  • First Cmd+S succeeds and the file reopens with state intact

2. Project Setup

Mental model — two tiers. Project Settings travels with the file (client-specific: site domain, KKE states, suggestion weights, statuses, assignees, saved filters). App Settings is per-user (auto-advance, visible clusters, API key, sidebar columns, column mapping).

  • Project Settings (File → Project Settings) — five tabs: Identity · KKE States · Suggestions · Migration · Saved Filters.
  • App Settings (⚙ button) — Appearance (System / Light / Dark) · Auto-advance · Show SME fields · Show Migration fields · Show Components cluster · Rubrics folder · Claude API key · Sidebar columns · Column mapping.
  • Turn on only the Show … toggles this engagement needs; blank metadata is hidden and every cluster collapses with a click.

Good end-state

  • Identity filled (at least Site domain — redirects/paths depend on it)
  • Custom KKE states / migration vocab defined if the engagement needs them
  • App Settings reflect how you work; Project Settings saved into the file
B · The core audit

3. Running the Audit Pass

Mental model — one row = one existing page. Selecting it loads the page in the browser and fills the field-bar clusters (Decide · Classify · Migrate · Components · CMS). You live in Decide; the loop is keyboard-driven.

  • Make the call: 1 Keep · 2 Kill · 3 Evolve · 4 Consolidate · 5 Exclude (0 clears). Auto-advance carries you on; ] jumps to the next unreviewed row.
  • Rationale & flags: Notes (dot when present); F flags/unflags (★); Assess runs the rubric.
  • Classify lightly: set Content Type (drives the crosswalk) — batch the rest later.
  • Browser: ← → ↻, viewport switcher (Auto / SM / MD / LG / XL), ◫ compare · 📷 screenshot · ⇊ extract content · 🔗 check links · ↗ open externally.

Good end-state

  • Every intended page has a KKE call (check with ])
  • Rationale captured where the call isn't obvious; tricky pages flagged (F)
  • Content Type set where it'll drive migration; saved

4. Finding the Work

Mental model — filters are stackable and AND-ed (text and KKE and group and field filters). The list always reflects the current filter, and the Multi-bar acts on exactly that set.

  • Search with a scope selector: All fields / URL / Title.
  • KKE filter is a checkbox dropdown (multi-select, OR-ed) including special filters: Unreviewed, Flagged, Duplicates, SME conflicts/pending, Consolidate (no/dead target), Shared nav, Needs placement, Suggested disagrees / ≠ your call.
  • Field filters (+ Field filter) on any column: is blank / is not blank / contains / equals / starts with / ends with. Unclassified is a shortcut for Content Nature is blank.
  • Save a combination (text + scope + KKE + group + field filters) and recall it; Cmd+F Global Search finds & navigates across all rows. In the Sitemap, Cmd+F searches the nav nodes instead (label, breadcrumb, number, path, notes, pattern, assignees) and the ◀/▶ buttons jump & scroll to each match, expanding collapsed branches as needed.

Good end-state

  • Scope matches what you're hunting; multi-check used for "either"
  • Field filters layered for precise slices (e.g. NavID is blank)
  • Recurring slices saved as named filters

5. Bulk Operations

Mental model — the Multi-bar acts on a target set: your multi-selection if any, otherwise the filtered rows. The label says which ("Apply to N selected/filtered:").

  • Define the target: filter only, or multi-select (Cmd+click toggle, Shift+click range). Selection wins when both apply.
  • Apply an action: Set KKE · Set Published Status · Set Content Type · Set Content Theme · Set Group · Set Primary Tag · Add Tag → pick value → Apply. Kill-cleanup prompts fire for pages with nav/redirects.
  • Batch assess: Project → Run Rubric on filtered rows… scores the set into Suggested_KKE.

Good end-state

  • The bar's label confirms the right target before Apply; filter spot-checked
  • Kill-cleanup handled; batch-assess for scoring, hand-set KKE for judgment

6. Tagging, Grouping & the Glossary

Mental model — three fields, different jobs: Group (one per page, the bucket), Primary Tag (one, the headline descriptor), Tags (many, finer CSV). The Glossary keeps terms consistent with a per-name definition.

  • Apply in the Classify cluster (Group / Primary are single-select with + New…; Tags is a chip input). Bulk via the Multi-bar.
  • Project → Edit Glossary… — markdown Notes per tag/group (empty entries pruned on save; travels in KKE_Glossary).
  • Export for Word… writes a styled .html key of every term + definition.

Good end-state

  • Every page has a Group; Primary Tag where one descriptor dominates
  • Tags drawn from a deliberate reused set; every active term defined
C · Classify for migration

7. Content Types & the Crosswalk

Mental model — three linked attributes: Content Type (what it is — the key), Renders as (Page / Fragment (embeddable) / Generated), Target Content Type (what it becomes). The Content Type Registry is the crosswalk — define once per type, every page inherits it, non-destructively.

  • Set Content Type as you audit (a → hint shows the mapped target). This is the one classification worth doing on the main pass.
  • Project → Content Type Registry… — per type: Renders as · Target Content Type · → Target Spec · Migration Track · Notes. Seed with defaults stages ~20. The editor also lists content types in use without a crosswalk (flagged “in use · no crosswalk”) so gaps are fillable; a Show all pick-list types toggle adds unused global dropdown values. Untouched surfaced rows aren't saved — only mapped ones persist.
  • Adding a type via the audit bar's + New content type… seeds a blank registry row automatically (skipping anything already covered) — the global dropdown and the per-project crosswalk stay in sync.
  • Defaults fill blank Renders as / Track / Target only (never overwrite). The Migrate cluster's Track shows a ghost suggestion when blank.
  • Verify: the Unclassified button finds missing Renders-as; Reports → Content Type Crosswalk… flags types with no entry.

Good end-state

  • Every keep/evolve page has a Content Type; registry covers every type in use
  • Renders as populated (Unclassified → 0); Target + Target Spec + Track mapped

8. Suggested_KKE

Mental model — a thin orchestrator over up to three sources — Rubric (rules), AI (Claude), GA (analytics composite). It combines them by weighted vote into one suggestion and never touches your human KKE.

  • Set up in Project Settings → Suggestions (GA mapping/weights, rubric folder, source weights).
  • Generate: Run Rubric on filtered rows… · AI Suggest for Unreviewed… (blank-KKE rows only, ~1s/row, Esc aborts) · Refresh GA KKE. Recompute Suggested KKE re-runs the combine.
  • Read: the Suggested_KKE badge (source prefix, ⚠ on disagreement; click for the breakdown). Sidebar filters Suggested disagrees / Suggested ≠ your call focus your judgment.

Good end-state

  • At least one source configured; weights reflect trust
  • Disagreements/mismatches reviewed; human KKE confirmed where it counts

9. Consolidate

Mental model — Consolidate merges a page's content into another (recorded in Consolidate_Into); the target survives (usually Evolve). Consolidated pages need no nav placement; the redirect resolver chases the target (cycle-safe). The app warns on a dead target.

  • One page: press 4 / click Consolidate → pick the target in the picker (sets Consolidate_Into + KKE, clears nav).
  • In bulk: Sitemap → Consolidation Candidates… lists nodes with 2+ pages; pick the target (→ Evolve), the rest become Consolidate.
  • Catch breaks: sidebar filters Consolidate (no target) and Consolidate → Kill/Exclude target.

Good end-state

  • Every Consolidate page has a live target (no "no target" / "dead target")
  • Targets survive as Keep/Evolve; redirects resolve to a real URL

10. Non-200 Triage

Mental model — a crawl is full of non-200 URLs (3xx/4xx/5xx) — mostly cleanup, not content decisions. Triage groups them by status code and sets a default KKE per group at once.

  • Project → Triage Non-200 Pages… (or the auto-offer on open) — one row per code with a pre-set KKE dropdown; adjust, leave blank to skip, Apply.
  • Sidebar status-code badges (amber 3xx, red 4xx/5xx) help you spot what's left. Triage never hides rows — a 404 might be a live page behind a wall.

Good end-state

  • Each code group given a deliberate action (or intentionally skipped) and applied
  • No unexpected red/amber rows left unreviewed
D · Collaborate & review

11. SME Review

Mental model — export → reviewer fills dropdowns → import → resolve. The SME needs only Excel; their columns (SME_Decision, SME_Notes, Content_Owner) merge alongside your audit — never overwriting your KKE.

  • SME → Export for SME Review… (optionally split by Content Owner); embedded dropdowns constrain choices.
  • SME → Import SME Decisions… merges by URL. Compare KKE vs SME… shows divergence; Resolve Conflicts… sets Final_KKE.
  • Reconcile inline with Show SME fields; sidebar filters SME conflicts / SME pending.

Good end-state

  • Imported; Compare reviewed; Resolve run (every reviewed page has a Final KKE)
  • SME conflicts / pending filters empty

12. Multi-auditor Merge

Mental model — merging reads the other auditor's file, matches rows by URL, and reports agreements vs conflicts (different KKE on the same page). You resolve conflicts — never silently overwritten.

  • File → Merge Auditor Decisions… → pick the other file. Empty cells fill automatically; conflicts open a resolution dialog (per-row, or bulk Accept All Theirs / Keep All Mine).
  • Related: File → Import/Merge fills only blank cells and can add new URLs.

Good end-state

  • Other file merged; every conflict resolved (0 remaining); saved as canonical
E · Architect the future site

13. Sitemap & IA

Mental model — audit rows answer "what about each existing page?"; the sitemap answers "what is the new site?". You connect them by placing Keep/Evolve pages onto nodes. The sitemap is the source of truth for breadcrumbs and computed URLs — renames cascade.

  • Open with Cmd+Shift+T (or the Sitemap tab). Drive need placement → 0: KKE = Keep + Evolve, field filter NavID is blank, then the audit bar's Sitemap button → Assign (use + Child to create a node inline). Starting empty? With no nodes yet, the Sitemap button offers an inline form (Label from the title, Slug from the URL) to create the first root node and assign the page in one step — no need to open the Sitemap view first.
  • Shape: rename/re-slug inline (cascades), drag to reorder/reparent, + Root Node / row +, ⧉ clone, Remediate. Set Node type, Collapse (bulk Collapse ✓ / Expand — summarizes a subtree in the Visual Sitemap), Reference, Phase.
  • Gaps: NEW = net-new; red empty leaf = assign / net-new / phase / delete; ⚠ duplicate IDs auto-renumbers. Read the stats line.
  • Decouple the three axes (all in the node editor): URL override (↪) publishes a page at an address off its menu position, re-rooting sub-pages; Breadcrumb parent (↰) sets an arbitrary on-page breadcrumb top (e.g. deep Accounting reads Home > Accounting) — optional Home prefix + advisory depth cap in Project Settings → Identity, and a Page Breadcrumb column in the Migration Tracker / nav & menu exports; and Menus (below) are independent of the tree. Containment, URL, breadcrumb, and menus are four separate things.
  • Visual Sitemap (toolbar Sitemap): the content IA as one interactive box tree rooted at the homepage. Click cards to collapse/expand, scroll to zoom, drag to pan, Fit. Branches auto-lay-out horizontal vs vertical by two thresholds (Vertical from depth, or if children ≥); right-click a node to force a direction or set its color. Settings panel: Layout (sizes/gaps), Colors (a rule engine — by depth / section / value, plus per-node overrides), Legend (editable labels), and Save as my defaults. Export an interactive HTML file for the client (collapse/zoom in any browser) or a one-page PDF. Also Sitemap Coverage & Net New Content Brief (the navigation hand-off report is now the Menu Report, in the Menus view).

Menus

Mental model — the tree says where content lives; menus say how people reach it — not the same thing. Menus are independent structures that reference content pages, so the same page can appear in several menus at different depths, and a menu's shape need not match the hierarchy.

  • Open the Menus tab (or Cmd+Shift+M). Left = your menus (drag to reorder); right = the selected menu. + New Menu, or Seed from content tree to mirror the in-menu nav nodes as a starting point, then edit independently.
  • Add a page from the audit view: the audit bar's Menu button adds the current page to a menu without leaving the audit. Since menus reference pages on the sitemap, it first makes sure the page is on the sitemap (prompting you to add it if not), then opens a chooser of your existing menus (plus + New menu…); with no menus yet, it opens a New menu dialog (Name / Placement / Description) and adds the page to it.
  • Items, three kinds: + Page (references a content page — live label/path, flags broken refs), + Link (external URL), + Header (label-only grouping). Switch a kind anytime via the page / link / header dropdown on the item.
  • Drag the ⠿⠿ grip to reorder or nest (top/bottom third = before/after, middle = nest). Flat or as deep as you like, per menu.
  • Per-menu context: a Placement (per-project vocab — Top bar, Footer, Overlay / Fly-out… add your own) and a free-text Description. Menus travel with the file.
  • Export… (CMS-agnostic): a neutral structure any platform maps from — choose all menus or the selected one, as a flat Excel Menus sheet or nested JSON. Page refs resolve to target URLs; no vendor model baked in.
  • Broken refs: if a page a menu references is deleted, the item shows (missing page) and a red ⚠ broken refs button appears — click to re-pick or remove each. Check before handoff.
  • Report: a tight hand-off doc (PDF / HTML) — one card per menu with its item tree, page-count badges on refs, ↗ links, ≡ headers, red missing on broken refs.
  • Sitemap: draws your menus with the same interactive engine as the Visual Sitemap (above) — each menu a tree stacked under its name, items colored by kind, headers dashed. Collapse/expand, smart horizontal/vertical layout with right-click overrides, the Settings panel (Layout / Colors / Legend), zoom/pan, and Export HTML (interactive) / Export PDF.

Good end-state

  • need placement = 0; no unexplained empty leaves; no duplicate NavID/slug warnings
  • Phased work marked; net-new intentional; big repeating branches collapsed in the sitemap

14. Build & Direction

Mental model — every build node carries direction for three roles — Builder, Writer, Migrator. Direction lives at two levels: type-level defaults on the Target Spec, node-level briefs that override. Write the brief once per spec; the rest follow.

  • Project → Target Spec Library… — each spec is a Page Template or Content Model (field schema) with three direction defaults: Writer brief · Build guidance · Migration mapping. Matched by exact name; 12 seedable defaults.
  • Annotate nodes in the editor's Build / Write / Migrate sections (Pattern, Page status, Builder, Build guidance, Writer, Writer brief, Migrator). Applying a Pattern fills blank briefs (a Keep/Append/Replace diff dialog guards populated ones).
  • Vocab: Project Settings → Migration (Page Statuses + the shared Builder/Writer/Migrator Assignees pool). Fragments are typed via Node type.
  • Worklists: Reports → Migration Direction Brief… — Role (Writer / Builder / Migrator) + Person, grouped by spec. Each node lists the source page(s) assigned to it, and any page absorbing others shows a merges N flag (the old pages being consolidated into it).

Good end-state

  • Every build node has a Pattern (each with a default brief, or one reference page)
  • Builder/Writer/Migrator assigned; status reflects reality; specs carry a migration mapping
F · Ship it

15. Redirects

Mental model — a redirect is needed for any Kill page and any page whose URL is changing. The app resolves destinations by priority (custom → nav node path → project default → blank). The literal 404 means "let it die" (distinct from blank = TBD).

  • Open with the Redirects tab / Cmd+Shift+R (lists Kill + URL-changed pages; fragments excluded).
  • Set efficiently: Re-derive from nav, the per-row nav picker, the 404 toggle, and Find/Replace (filters to matches; Replace All). Destinations also resolve on Save.
  • Validate & export: Migration → Redirect Chain Check…; Export Redirect Map (CSV)…; Reports → Redirect Map Report… (Kill / URL-changed / intentional 404s).

Good end-state

  • Every Kill/URL-changed page has a destination (or an intentional 404)
  • Re-derived after the tree was finalized; chain check clean; map exported

16. Producing the Outputs

Mental model — reports are read-only views generated on demand; each exports to PDF or HTML (HTML opens cleanly in Word). Three audiences: stakeholder narratives, IA/structure, delivery/engineering.

  • Stakeholder: Executive Summary · Content Inventory by Section · SME Review Status.
  • IA & structure: Menu Report · Sitemap Coverage Report · Content Type Crosswalk · Component Inventory.
  • Delivery: Migration Direction Brief · Migration Checklist · Net New Content Brief · Redirect Map Report.
  • The Migration menu holds export/validation tools; the Progress Dashboard (Cmd+P) gives live completion stats.

Good end-state

  • Executive Summary + Content Inventory for the client; IA reports if the tree is in scope
  • Delivery reports generated for the build team, each in the recipient's format

17. Migration Tracker Hand-off

Mental model — the engineering deliverable: one multi-sheet .xlsx generated from current state, re-exported as the audit evolves. Run the Pre-Handoff Check first.

  • Migration → Migration Tracker… — toggle sheets/options, then export ({project}-migration-tracker-YYYY-MM-DD.xlsx).
  • Sheets: Nav Plan (build metadata per node) · Source Pages (audit rows joined to nodes) · Redirects (Kill + URL changes; 404 as intentional deindex) · Archive (Kill rows + notes/tags).
  • Scope the Nav Plan: pick which columns appear, and tick Only nodes matching the active Build filter to export just the nodes that match the Build filter you set in the Sitemap (e.g. one assignee, one status).
  • Quick one-sheet export: in the Sitemap, set a Build (and/or Phase) filter, then Export → Filtered nodes → Excel… — choose columns and export just those rows to a single sheet ({project}-nav-nodes-YYYY-MM-DD.xlsx).

Good end-state

  • Pre-Handoff clean before export; toggles set for this hand-off
  • Nav Plan carries the build metadata; Redirects matches the map; dated filename

18. Pre-flight & Hand-off

Mental model — the Pre-Handoff Check rolls every validation into one pass/issue report — a gate, not a fix. Fix what it flags, re-run, repeat until clean. The change log is the automatic audit trail.

  • Migration → Pre-Handoff Check… checks: every page has a KKE call · Consolidate targets set & live · no redirect chains · no duplicate nav IDs · no empty nav leaves (nav checks skipped without NavStructure). Work top-down, re-running after each batch.
  • Change log: KKE / SME / Final changes are appended to the KKE_ChangeLog sheet on save (accumulates across sessions).

Good end-state

  • Pre-Handoff reports Ready for handoff (0 issues)
  • Final save (change log written); reports + Redirect Map + Tracker generated
G · Power features

19. Templates

Mental model — two unrelated systems. Audit templates (.kke-template.json) snapshot your setup; report templates (Markdown + Mustache) shape how a report renders (currently the Migration Direction Brief).

  • File → Save / Load Audit Template… — carries field config, vocabularies, KKE states, column mapping, identity (not page data).
  • Report templates: in Documents → Transmission → templates; FIELDS-*.md document the placeholders; a template declares appliesTo: assignee-brief in frontmatter; pick it in the Direction Brief dialog.

Good end-state

  • Reusable audit template saved; new projects bootstrapped via Load
  • Custom report template's placeholders match its FIELDS-*.md

20. Component Inventory

Mental model — a component is a UI building block (hero, card grid, accordion), distinct from content type — a page can carry several. Tag pages with the components they use (Design_Patterns); the report turns tags into frequency-and-reuse insight.

  • Enable Show Components cluster; + Add component picks from a categorized library (complexity badges) or creates one inline.
  • Project → Component Library… — curate / Seed defaults (57 built-ins).
  • Reports → Component Inventory… — frequency + KKE breakdown, one-off flags (≤2 pages), top co-occurring pairs (often your real page templates).

Good end-state

  • Components tagged from a consistent library; library curated/seeded
  • Report generated/exported; one-offs reviewed

Tip: pattern auditing is a second-pass activity — filter to Keep + Evolve first (no value cataloging Kill pages).

Rubric DSL

Rubrics are markdown files (one per status) in a configurable folder; each has ## Field Rules (auto-evaluated — the status with the most passing rules wins) and ## Content Rules (plain-English checklist for manual / AI review).

# Keep

## Field Rules
- Status Code is 200
- Indexability Status is Indexable
- Word Count > 500

## Content Rules
- Page provides comprehensive coverage of its topic
- Content is current and regularly maintained

Field rule operators

OperatorExample
is / is notStatus Code is 200
is empty / is not emptyMeta Description 1 is empty
contains / not containsTitle 1 contains buy
starts with / ends withAddress starts with https://example.com/blog
> >= < <=Word Count > 300
and (compound)Status Code >= 300 and Status Code < 400

All comparisons are case-insensitive. Edit rubrics in-app via App Settings → Rubrics → Edit; bind a folder to a specific file per filename. With a Claude API key set, AI Assess / Batch Assess evaluate content rules too (results in _AssessedAt / _AssessmentResult).

Your custom extractions are safe. Transmission stores every column in your crawl losslessly — including any custom extraction columns you set up in Screaming Frog (XPath/CSS/regex pulls: CMS IDs, author bylines, publish dates, schema markup, component flags, etc.). Nothing is dropped or renamed when you open the file or convert it to a .transmission project, and everything round-trips back out intact on Export Full Workbook. Those columns aren't just preserved — they're usable: surface any of them in Table View, pin them to the field bar (Preferences → Sidebar columns / field picker), or filter on them with + Field filter (e.g. CMS Template is not blank). The app treats your columns and the audit columns the same way.

Tips & Best Practices

Speed up your audit

  • Use 1–5 for KKE and enable auto-advance to fly through pages; ] jumps to the next unreviewed.
  • Set up rubrics early — even a few field rules per status catch the obvious pages.
  • Use Batch Assess / AI Suggest for Unreviewed to seed Suggested_KKE, then confirm.

Stay organized

  • Assign Groups early; use Primary Tag for the dominant characteristic.
  • Flag pages to revisit with F; save named filter combos for views you return to.

Work with your team

  • Use audit templates for consistent setup; export SME subsets by Group or Owner.
  • Merge parallel auditors' files; the changelog tracks every decision change.

Sitemap, redirects & hand-off

  • Place every Keep/Evolve page (need placement → 0) before deriving redirects.
  • Re-derive redirects from nav after restructuring; run the chain check before export.
  • Run the Pre-Handoff Check last — fix what it flags, then export the Migration Tracker.
